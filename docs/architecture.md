# Architecture — per-module catalog

The load-bearing **constraints** and the **test harness** live in `CLAUDE.md` (`## Architecture`) — read those every session. This file is the detailed per-file reference for `web/js/`; read it when working inside a specific module.

Single-page Thai vocabulary/script trainer PWA with SM-2 spaced repetition. `web/index.html` is the HTML + CSS shell (all screens and styles); app logic lives in `web/js/` as classic scripts sharing globals (see CLAUDE.md for the no-ESM / load-order constraint).

## Files

- `web/index.html` — HTML + CSS shell only: all screens and styles. App logic lives in `web/js/`.
- `web/js/mobile.js` — touch detection via `pointer: coarse` (deliberately not `ontouchstart`, so touch-screen laptops stay "desktop") and iOS detection (including iPadOS posing as MacIntel). Tags `<body>` with `.mobile`/`.ios`. CSS convention: wrap keyboard-shortcut UI in `class="kb-hint"` (hidden on mobile) and touch instructions in `class="touch-hint"` (shown only on mobile).
- `web/js/tts.js` — speech has two paths, tried in order: Capacitor native TTS plugin (`window.Capacitor.Plugins.TextToSpeech`) → Web Speech API. `_tts.speak(text, btn, rate)` accepts a string or an **array of parts** (optional `rate` — default 0.85; the course's 🚀 street-speed buttons pass 1.25, wired through both the web and Capacitor paths); parts are spoken as separate utterances with a ~400 ms pause (Thai voices read a comma inside one utterance straight through, flattening it into even syllables). Single letters must always be spoken via `letterSpeechParts(ch)` (in `thai-script.js`) which produces ["sound", "name"] (ก → ["ก", "กอไก่"] — the name spelled solid so the voice reads it as one word, covering all consonants, single-mark vowels, and compound vowel patterns); it passes non-letters through as a single part, so wrapping is safe. `letterSpeech(ch)` is the joined-string form for display/comparison, not for speaking. On iOS Web Speech, `speak()` must stay inside the user-gesture call stack, so the 50 ms post-`cancel()` delay (a Chrome workaround) is skipped there, and a silent utterance on first touch unlocks speech. **Never let speech gate a state transition** — update game/UI state first and speak last (a throwing TTS path once froze Connect สี่ mid-turn).
- `web/js/audio.js` — chiptune SFX + background music for the games, synthesised live with the Web Audio API (no audio assets, works from `file://`). `_audio.sfx(name)` for one-shot effects, `_audio.music(track)`/`_audio.stop()` for the step-sequencer loops; `_audioScreen(id)` (called by `showScreen` in app.js) maps game screens to tracks, so entering a game starts its loop and navigating anywhere else stops it. The AudioContext is created lazily on first use — always inside a user gesture, satisfying autoplay policies. Mute (`_audio.toggleMute()`, persisted under `"thaicab_muted"`) is exposed via `.audio-mute-btn` buttons in the game footers; `main.js` syncs their glyphs at init.
- `web/js/game.js` / `tutor.js` / `soi-buakhao.js` / `connect4.js` / `baht-bus.js` / `clock.js` — the games. Baht Bus teaches Thai numbers: `_bbThaiNum` composes 1–999 including the irregulars (เอ็ด for a trailing 1 above 10, ยี่ for 20), and the fare/negotiation helpers are pure; its sunset scene reuses `_BUS_ROWS`/`_WALK_FRAMES` from game.js (safe cross-file because they're only referenced inside functions, after all scripts have loaded). Walking Street pops via `_gPopBubble`, shared by desktop keyboard (`_gKey`) and mobile (`_gKbdPress`/`_gKeyIdx` — on mobile the tutor's on-screen Kedmanee keyboard, built by the shared `_tBuildKbdInto` from tutor.js, replaces the reference strip; every tapped key is spoken, and bubbles carry no Latin hints). The tutor and Walking Street must agree on the Kedmanee mapping (`TUTOR_ALL` vs `GAME_LETTERS` — a test enforces this). **Last Bus** (`clock.js`, nav `L`) teaches the Thai six-hour clock, the one number skill Baht Bus doesn't touch: `thaiTime(h, m)` is the whole system in one pure function (ตี 1–5 / โมงเช้า 6–11 / เที่ยง / บ่าย 13–15 / โมงเย็น 16–18 / ทุ่ม 19–23 / เที่ยงคืน, plus ครึ่ง and the นาที fallback), and it reuses baht-bus.js's `_bbThaiNum`/`_bbRomanNum` for number composition (inside functions only, so script order stays free). The game is built on one fact: `_ckSpokenNum(h)` collides across cycles (3 → ตีสาม 03:00 / บ่ายสามโมง 15:00 / สามทุ่ม 21:00), so `_ckConfusable`/`_ckDistractorHours` make the wrong options the *pedagogically* wrong ones rather than random times. `thaiTimeAlts(h, m)` carries the readings that are equally correct but aren't canonical (16:00 บ่ายสี่โมง, 17:00 บ่ายห้าโมง, 12:00 เที่ยงวัน — `hourOnly`, since เที่ยงวันครึ่ง isn't said); a setting round grades on the hour, so it speaks the alternate about half the time, and every verdict card names it. Archaic forms (ย่ำรุ่ง, ย่ำค่ำ, สองยาม) and the older โมงเช้า counting are deliberately excluded. Rounds alternate reading (digits → pick the Thai) and setting (hear the Thai → set a clock face), the same listening/reading split Baht Bus uses; `_ckPlan(rand)` takes an injectable rng so the ten-round plan is testable. All pure helpers are DOM-free at load and covered by `tests/js/clock.test.js`, which pins every hour of the day literally.
- `web/js/srs.js` — SM-2 engine plus session-queue helpers (`requeue` for same-session relearning of failed cards, `dueForecast` for the stats chart). Progress lives in localStorage under the key `"thaicab_progress"`. `dueCards`/`peekCard` are deliberately read-only: never insert records on a read path, only `getCard` on a review/write path (a past bug persisted empty records for every key merely displayed; `app.js` still prunes those on load).
- `web/js/data.js` — all Thai data (words, consonants, vowels, tones); edit it directly, it is the source of truth. (It was originally generated from a Python app that has since been removed from the repo.)
- `web/js/wordcard.js` — the **shared word-card modal** (decomposition, translation, example sentences, script/word tooltips), extracted from ui.js so The Last Baht Bus can vendor an identical copy. THIS repo is the source of truth; after editing wordcard.js (or tokeniser.js/thai-script.js/data.js/examples.js), run `node scripts/sync-vendored.mjs` to re-copy the vendored set (plus `tests/js/wordcard.test.js`) into The Last Baht Bus — it stamps each copy with a VENDORED banner and is idempotent; `--check` verifies sync and exits non-zero on drift (see the "Vendored files" section). `makeTokeniser` (tokeniser.js) enforces one invariant worth knowing: a token boundary may never fall inside a Thai character cluster — not before a dependent sign (ั ิ ี ุ ่ ้ ะ า ำ) nor after a leading vowel (เ แ โ ใ ไ) — via `_tkLegalBoundary`. Without it greedy matching emits tokens like "ี้" that render as tofu; it was doing so on 15 of the 940 example sentences. `segment.js` reuses the same predicate. wordcard.js is self-contained: local `_wcEsc`, lazy `_wcMap()` that uses the host's WORD_MAP when present, DOM guarded at load (vm-safe). Needs `#wc-overlay`, `#script-tooltip`, `#word-tooltip` elements plus the wc-/decomp-/example-/st-/tt- CSS in the host page. `openWordModal([thai, rtgs, english])` is the public entry. Its pure helpers (`_wcEsc`, `_wcMap`, `_scriptTooltipHtml`) are covered by `tests/js/wordcard.test.js` — vendor that test into The Last Baht Bus alongside the file.
- `web/js/curriculum.js` + `learn.js` — the **Guided Course** (read-first, per the learning-redesign brief): curriculum.js is pure data + helpers (LETTER_BATCHES frequency ladder; `courseDecodable`/`courseNewWords` compute decodable word pools live from WORDS — 8→745/916 across eight batches; GRAMMAR_LESSONS scenario chunks g1-g6; COURSE spine; `courseGrade` maps recall onto SM-2 quality: wrong 1 / retry 2 / right 4 / fast 5). learn.js is the runner: path screen with 80% first-try mastery gates (`soisanuk_path` in localStorage), `_unitQueue` (pure, tested) builds each unit — due-review warmup, glyph intros, MC both directions with same-POS distractors, typed-English (`_enMatch`, lenient), Kedmanee typed-Thai (tutor's `_tBuildKbdInto`, every key spoken, decodable ≤4-glyph targets only), corpus cloze from EXAMPLES, timed speed reads, 5-pair match, listening in pick-script and pick-meaning modes. Missed answers pause with a word-card (openWordModal) button. Grades write to the SAME SM-2 store as every other mode. **Engagement layer** (all in learn.js): 🏁 speedometer (`path.best` personal-best read ms via `_bestUpdate`, chips on the path), ▶ Continue + 🔥 streak (`soisanuk_streak`; `_streakBump` pure day-roll with `maxDays`/`bestDay`; `startContinue` picks due reviews → next unit → speed round; pseudo-units use `_lu.idx < 0` and skip the mastery gate), signage lesson g5 renders chunks in three sign registers (`item.sign` 0-2 → `.learn-sign-N`), 📍 placement (`startPlacement`, `_placementCut` 80%/batch prefix, `_placementApply` marks units `placed`) + `_levelName` Pattaya levels in the path header, 🏆 Records screen (`showRecords`), and 🚌 Words from the bus (`busWords(save, words)` maps LBB's `lbb_save.thaiSeen` — same origin — onto WORDS; phrases yield component words). Any top-level DOM touch must guard `typeof document !== "undefined"` for the vm tests. Both files are DOM-free at load (vm-tested in tests/js/learn.test.js). **The tone unit** (`COURSE` id `tone1`, after the "rising and falling" reading batch) teaches Thai tone rules: a `toneIntro` card (the mid-class minimal set กา/ก่า/ก้า/ก๊า/ก๋า under all five tones), an interactive `tonecalc` (class × vowel length × mark → tone, live), `toneear` drills (hear a tone, pick the script — mid-class hosts only, since mid + the four marks spans all five tones), and `toneread` drills (name a real word's tone — deliberately NOT graded into that word's vocab SRS, since naming a tone is a separate skill from knowing the word; both tone drills only gate the tone unit itself). Its pure data — `toneMinimalSet`, `TONE_READ_WORDS` — is in curriculum.js; `TONE_ORDER`/`TONE_LABELS`/`TONE_COLORS` (the tone display contract) moved to thai-script.js (vendored) so LBB gets them too — see "The tone engine" below.
- `web/js/reader.js` — the **Graded Reader** (📖, nav `D`): comprehensible-input reading over the EXAMPLES corpus. `readerGrade(thai)` scores a sentence by the latest `LETTER_BATCHES` rung its glyphs need; `readerFeed(maxBatch)` returns every sentence decodable by a level, easiest-first, de-duped. Four levels (`READER_LEVELS`, cutoffs 4/6/7/8 → 12/119/316/849 sentences on the current corpus; the top tier also admits consonants the course never teaches). The reading card reuses the word-card tokeniser (tap any word → `openWordModal`, same SRS store), read-along audio (🔊/🚀), and a persisted tone-colour toggle (`soisanuk_tonecolor`). App-only (not vendored); pure grading helpers are DOM-free and vm-tested in `tests/js/reader.test.js`. Loaded after learn.js, before backup.js; add to `sw.js` PRECACHE.
- `web/js/segment.js` + `web/js/lexicon-th.js` + `web/js/paste.js` — **Paste Text** (📝, nav `P`): the open-text counterpart to the graded reader. `segment.js` is a dictionary-DP segmenter (newmm-style maximal matching) over a 12k-word frequency-ranked lexicon; it is deliberately **not** `makeTokeniser`, because greedy longest-match over the ~950-word curriculum map degrades badly on arbitrary text — it matches มา inside มาตรการ and glosses it "to come". Measured on 30 out-of-curriculum sentences: curriculum+greedy 84.8 boundary-F1 with 23.9% of characters unmatched, this 95.0 with 0% (full write-up: `docs/chrome-extension-handoff.md` §6). A known word costs `log(rank)` — its Zipf surprise — and an unknown cluster a flat `_SEG_UNKNOWN_COST`; the cheapest whole-string segmentation wins, which greedy cannot do because it can't back out of a long match. Boundaries are constrained by `_tkLegalBoundary` (tokeniser.js), so both segmenters agree on where a cut may fall. `lexicon-th.js` is **generated** — `node scripts/build-lexicon.mjs <words_th.txt> <tnc_freq.txt>` from the PyThaiNLP corpus (both files CC0-1.0; source URLs in the script header) — and ships the word list in frequency order with no counts, since rank-derived cost measured within 0.5 F1 of the real corpus frequencies at half the payload. It is ~240KB and **deliberately not in `sw.js` PRECACHE**: `_segLoad` injects it as a `<script>` tag (not `fetch`, which is blocked on `file://`) the first time the screen is used, and the service worker's runtime cache keeps it offline-available afterwards. `gloss.js` + generated `gloss-th.js` add the dictionary layer — `thaiGloss(word)`/`thaiRoman(word)` return the curriculum's own gloss and romanisation when there is one (hand-written for this course, and it comes with examples) and otherwise a short English gloss plus a derived romanisation from Wiktionary. **The romanisation is converted, not copied.** kaikki tags three systems and none matches the house style: Paiboon writes `dtam-rùuat`/`sǔai`, Royal Institute `tam-ruat`/`suai`, the course `tam-rùat`/`sǔay` — i.e. Paiboon's tone marks over RTGS-style consonants. `build-gloss.mjs` converts Paiboon (RI is unusable, it carries no tone at all) by remapping onsets (`g`→`k`, `bp`→`p`, `dt`→`t`, `k`→`kh`, `p`→`ph`, `t`→`th`, `j` unchanged) and IPA vowel letters (`ɛ`→`ae`, `ɔ`→`o`/`oo`, `ʉ`→`ue`/`uue`, `ə`→`oe`/`ooe`), lifting the tone diacritic out and re-seating it on the first vowel. Validated against the 764 curriculum words present in both: **86.1% exact**, and of the 106 misses 67 differ only in vowel-length spelling and 15 in `-ai`/`-ay`. The ~24 that disagreed on a TONE MARK are the ones that must not ship — a romanisation reading "rising" beside text coloured "falling" is worse than none — so every derived form is cross-checked against `syllableTone` and **dropped on conflict** (31 dropped; 99.2% of glossed words keep a romanisation). That check is pinned by a test. Several of the original disagreements turned out to be errors in `data.js` rather than in Wiktionary (`คะ`, `กรุณา`), so the comparison doubles as an audit of the course's own romanisations. **Separate file from the lexicon for licence reasons, not tidiness:** `lexicon-th.js` is CC0 and free of obligations, `gloss-th.js` is derived from English Wiktionary via kaikki.org and carries **CC BY-SA 3.0** — attribution (rendered as `.paste-credit` on the screen) plus share-alike on that file. Keep them separate so the boundary stays obvious. Generated by `node scripts/build-gloss.mjs <kaikki.org-dictionary-Thai.jsonl>`; the generator escapes backslash-then-quote and round-trips the file it wrote, because one real Wiktionary gloss ends in a backslash and silently merged two rows. Do **not** reach for PyThaiNLP's `thai_dict` corpus instead: it is extracted from THAI Wiktionary and defines Thai in Thai (เดิน → "ยกเท้าก้าวไป"). Coverage is 63.4% of the 12k lexicon but heavily front-loaded — 97% of the top 1,000 words by frequency, 86% of 1k–3k, 49% of the 6k–12k tail — so ordinary text is glossed almost completely. `paste.js` renders the result — every token is tappable, and the analysis degrades honestly: curriculum words open the full card with romanisation and examples, Wiktionary-known words open it with a gloss and a derived romanisation but no examples, and anything else opens it with no gloss at all. In both non-curriculum cases the character decomposition is auto-expanded (wordcard.js keys that on the word having no EXAMPLE SENTENCE — the honest test for "this card has nothing else to show", and the only one that survives a Wiktionary word arriving with both a gloss and a romanisation), because the script/tone engine works from spelling alone and needs no dictionary. Tone colour only appears where `toneOfWord` will vouch for it. The 🎨 toggle shares the reader's `soisanuk_tonecolor` preference via `_readerSetColor` (**not** `_readerToggleColor`, which ends in `_readerShow()` and would navigate away). Loaded after reader.js; `segment.js`/`gloss.js`/`paste.js` are in PRECACHE, the two generated data files are not. App-only (not vendored); `segment.js` and `gloss.js` are DOM-free at load and vm-tested in `tests/js/segment.test.js` / `tests/js/gloss.test.js`.
- **Romanisation** — the app writes ONE hybrid scheme, and it is deliberate. `data.js` column 1 is the single source of truth for it; `examples.js`, `curriculum.js` and every generated romanisation must match. **RTGS-style consonants** (`ph`/`th`/`kh`; `k`/`p`/`t` where Paiboon writes `g`/`bp`/`dt`) carrying **Paiboon's tone diacritics** and **explicit vowel length** (`aa`/`ee`/`oo`/`uuea`). Measured over the 950 words: 769 carry a tone mark (the rest are mid, unmarked), 294 use `ph`/`th`/`kh`, 278 double a long vowel, zero use raw IPA letters.

  Why not either pure system:

  - **Pure RTGS** is what Thailand actually signs in — road signs, passports, menus, "Sukhumvit" — so it is the spelling a learner meets outside the app. But it discards tone *and* vowel length, which for a tone trainer is fatal: five separate curriculum words collapse onto `khao` (เขา *khǎo* he/she · เข่า *khào* knee · ข้าว *khâao* rice · ข่าว *khàao* news · เข้า *khâo* enter), and four onto `ya` (ย่า/หญ้า/ยา/หย่า). A romanisation that cannot tell those apart is useless to the drills.
  - **Pure Paiboon** keeps tone and length but respells the consonants (`gin`, `bpai`, `dtam`). The learner would carry two mappings — one for the app, one for every sign in the country — and only the second is out in the world.

  The hybrid keeps the letter shapes the learner will actually encounter and adds back exactly what RTGS deletes. **The cost is that it matches no external source**, which is why importing romanisation from a dictionary needs a converter and a validation pass rather than a field copy — see the Paste Text entry above, and `docs/chrome-extension-handoff.md` §8.

  This has drifted twice (the 2026-08 review found `curriculum.js` on a second `bp`/`dt`/`aaw` scheme — spec P2.3; a later sweep found 19 Paiboon spellings still in `data.js`/`examples.js`), so `tests/js/data.test.js` now pins it. It is a data-entry slip, not an open design question: when adding vocabulary, copy the scheme.
- **Tone colouring** (curriculum.js): `toneOfWord(text)` returns a word's tone only when it's safe to paint one colour — it reads the RTGS from `WORD_MAP`/`WORDS` and returns `null` for multi-syllable words (a hyphen/space in the romanisation) so a two-syllable word like เวลา (wee-laa) is never mis-coloured. `toneColorHtml(thai)` tokenises and wraps each monosyllable in a `TONE_COLORS` span, leaving the rest plain. Used by the reader; both share `toneOfWord`.
- **The tone engine** (`web/js/thai-script.js`, tests in `tests/js/tone.test.js`): `toneFromParts(cls, {mark, live, shortVowel})` is the pure rule table (mid/high/low × the four marks × live/dead), and `syllableTone(syllable)`/`syllableToneInfo(syllable)` parse ONE written syllable and return its tone (or `null` when the shape can't be read confidently — silent letters, odd vowels — so callers never show a wrong tone; for any text that isn't already known-monosyllabic, call `toneOfWord` (curriculum.js) instead, which guards on the word's romanisation). It reads consonant class from `CONSONANTS[i][2]` and final-liveness from `CONSONANTS[i][5]`, and handles ห/อ leaders, initial clusters (ควบกล้ำ — `_CLUSTER_SECONDS`/`_isClusterPair`, with guards for a trailing ร/ล/ว that is really a final (พร) and for C+ว+final that is really the reduced ◌ัว (ควบ); `syllableToneInfo` reports the second member as `cluster`), the consonant-letter-final compound vowels (◌อ, เ◌ือ, ◌ัว, เ◌ีย), bare ◌ือ, and reduced ◌ัว (the ั dropped before a final, e.g. สวย/ขวด). `TONE_ORDER`/`TONE_LABELS`/`TONE_COLORS` here are the single source for the tone vocabulary's order/display name/colour — `data.js`'s `TONES` rows must stay in `TONE_ORDER` order (enforced by a test, not by derivation). Validated against real single-syllable words in the test.
- `web/js/home.js` — the **desktop home pane**. On desktop the sidebar is the nav, so the main pane had nothing to do: measured 6.8% of a 936x900 area covered (a wordmark, a duplicate of the sidebar's stats line, and an arrow pointing back at the sidebar). It now renders a ▶ Continue call-to-action, four stat tiles, a 7-day review forecast and a tap-to-open word strip — 33.8% covered. Everything READS existing state (`srsStats`, `dueForecast`, `_streakLoad`, `_pathLoad`); nothing new is persisted. The CTA's headline comes from `continuePlan()` (learn.js), the same decision `startContinue()` acts on, so the card can never promise something the button won't do. Renders only when `matchMedia("(min-width: 701px) and (min-height: 500px)")` matches — mobile keeps the full menu list in that screen and `#menu-welcome` stays hidden — and re-renders on `showMenu()` and on crossing that breakpoint. Pure helpers (`homeCta`, `homeStats`, `homeForecastBars`, `homeWordPicks`) are DOM-free and vm-tested in `tests/js/home.test.js`. Loaded after idioms.js, before main.js; add to `sw.js` PRECACHE.
- `web/js/backup.js` — Backup & Restore + exports under More: JSON backup of both stores with **merge-on-import** (`backupMerge`, pure: more-reviewed card wins, done units stay done), share-sheet-first delivery (`_shareOrDownload`), `backupPersist()` (navigator.storage.persist, called from main.js), and deck exports: Anki TSV (`ankiTSV`), CSV, Quizlet, printable list. `.apkg` with scheduling state is deferred to a future backend (see memory).
- `web/js/sessions.js` — all study modes. Rating flows go through `_buildRatingHandler`, which also handles the undo snapshot and lapsed-card requeue; new rating-based modes should use it rather than calling `reviewCard` directly.
- `web/js/numbers.js` — number flashcards (`NUM_CARDS`, `startNumFlash`) and reference charts (`showCharts`, `showChartTab`). Builds the consonant, vowel, tone, and numbers chart HTML dynamically; calls `vowelDisp`/`letterSpeechParts` from thai-script.js. The consonant chart has an alphabetical/by-class order toggle (`_setAlphaOrder`, persisted under `soisanuk_chartorder`). DOM-free at load time and fully vm-testable. Loaded after baht-bus.js, before main.js.

## Vendored files (The Last Baht Bus)

The Last Baht Bus (`/Users/mario/projects/last-baht-bus`) reuses the shared Thai stack — `data.js`, `examples.js`, `tokeniser.js`, `thai-script.js`, `wordcard.js` — plus `tests/js/wordcard.test.js`. **This repo is the source of truth; edit here, never in LBB.** `scripts/sync-vendored.mjs` is the single sync path: it writes each copy prefixed with a `// VENDORED from …` banner (so an LBB copy can't be mistaken for an editable original), is idempotent, and takes `--check` to verify sync without writing (exit 1 on drift — wire it into a pre-commit or CI step if drift ever bites). Override the LBB location with `--dest <dir>` or `LBB_DIR=<dir>`. Don't hand-copy these files: a manual copy drops the banner and reintroduces the drift this script exists to prevent.

## Capacitor native trees (Android / iOS)

`android/app/src/main/assets/public` and `ios/App/App/public` are Capacitor's packaged copies of the entire `web/` directory (same app, not a fork — no banner, straight mirror). They're gitignored (Capacitor's own nested `.gitignore`s exclude them), so nothing here ever shows up in a diff — this is purely local build-input hygiene. `node scripts/sync-vendored.mjs` (the same script as the LBB job above, run together) also mirrors every file under `web/` into both trees, skipping a target entirely if that native project isn't checked out; `--check` reports `DRIFT` per file without writing, and also `ORPHAN` for any target file with no matching `web/` source (a rename/delete this mirror would otherwise miss) — write mode deletes orphans, same as `npx cap copy` regenerating the tree would. Capacitor's own runtime shims (`cordova.js`, `cordova_plugins.js`) are the only files in the target this never touches. `npx cap copy` (from `@capacitor/cli`, already a devDependency; `capacitor.config.ts` sets `webDir: 'web'`) does the same job and is the canonical tool for it — run either before a native build; the script exists so `--check` can catch drift without remembering to run `cap copy` first. `--dest <dir>`/`LBB_DIR` only retarget the LBB job — pass `--no-cap` alongside `--dest` if you're testing against a scratch LBB checkout and don't want that side effect on your real `android/`/`ios/` trees.
